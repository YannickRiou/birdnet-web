Everything you need to understand, run, test, change and deploy Piaf without outside help. Code comments and the user interface are in French; this handbook is in English. Identifiers (file names, functions, constants) are quoted exactly as they appear in the code.

1What Piaf is

Piaf identifies birds by their song, entirely in the browser. It is a static, installable web app (PWA) built on BirdNET V2.4 (a TensorFlow.js export of the Cornell Lab / Chemnitz model). It exists so that people whose phone cannot install Merlin Bird ID (for example an iPhone 8 stuck on iOS 16) can still identify birds. It also runs on recent phones and desktops.

Design constraints that explain most decisions in the code:

  • No server, no build step. Plain ES modules in the page, a classic script in the Web Worker. Hosting is GitHub Pages, which cannot set custom HTTP headers.
  • Everything on the device. Audio never leaves the phone. Only a species' scientific name is sent to iNaturalist, to fetch a photo.
  • Must run on an iPhone 8 (iOS 16, Safari): little memory, a slow CPU/GPU, microphone stops in the background. One analysis of a 3 s window must stay under 1500 ms (the hop is 1.5 s).
  • Works offline after the first visit (about 26 MB model + 15 MB geographic model).

Tech stack: TensorFlow.js 4.22.0 (WebGL / WebAssembly / CPU backends), Web Audio (AudioWorklet), Web Workers, Service Worker, localStorage. Dev tooling: Node (checks, vendoring) and Python (model conversion, icons).

3Quick start

Prerequisites:

  • A recent Chrome/Edge/Firefox/Safari.
  • Python ≥ 3.8 (for npm run serve, build_model.py, make_icons.py).
  • Node.js + npm (only for npm run check and npm run vendor).
  • model/ and vendor/ are already committed: you can run the site without installing anything.
git clone https://github.com/YannickRiou/birdnet-web.git
cd birdnet-web
npm run serve            # = python -m http.server 8080

Open http://localhost:8080 (stop the server with Ctrl+C). localhost counts as a secure context, so the microphone, the service worker and AudioWorklet all work. Any other host needs HTTPS.

Optional, to run the model check and to get the official sample:

python tools/build_model.py   # downloads zips into .cache/, extracts .cache/orig/ (sample.wav, official model)
npm install
npm run check

Set your own git identity in the repo (it uses a local identity, not a global one):

git config user.name  "Your Name"
git config user.email "you@users.noreply.github.com"

Commit messages are in English.

Useful URL parameter: ?backend=webgl|wasm|cpu forces a compute backend (see Backend choice).

4Architecture and data flow

Three execution contexts cooperate: the UI thread (page), the audio rendering thread (AudioWorklet) and the worker thread (engine-worker.js).

Key rule

Audio samples never touch the UI thread. The worklet gets a MessageChannel port whose other end is transferred straight to the worker.

The same flow, step by step:

  1. Microphone. getUserMedia({echoCancellation:false, noiseSuppression:false, autoGainControl:false, channelCount:1}) feeds a MediaStreamSource in an AudioContext running at the device sample rate.
  2. Worklet (js/capture-worklet.js, node capture): linear resample to 48 kHz mono, cut into 100 ms blocks (4800 samples). Blocks travel on the transferred MessageChannel port, transferred, not copied.
  3. Analyser (fftSize 1024): getByteFrequencyData() each frame, drawn by js/spectrogram.js (magma colormap, 0-12 kHz, UI thread, canvas).
  4. Worker (js/engine-worker.js): ring buffer of 3 s (WINDOW = 144000 samples); every HOP = 1.5 s, if not busy, it copies the latest 3 s, runs BirdNET (TF.js) to get 6522 sigmoid scores, and keeps the top 5 scores ≥ 0.1. It posts {type:'result', detections:[[index, score],...], ms}.
  5. UI (js/app.js, onDetections()): drop NON_SPECIES, drop scores below the user threshold, apply the geo filter (drop species with geoScores[index] < 0.03), update the detected map, rerender() the species cards.
  6. Then asynchronously: js/species-info.js (iNaturalist photo, 1 request/s) and js/lifelist.js (when the user taps "+ Ma liste").

Points worth knowing:

  • Slow devices skip windows. schedule() in the worker returns immediately if busy. When an inference finishes, it calls schedule() again, which analyses the most recent 3 s (not the next sequential window). A phone taking 3 s per inference simply produces a result every 3 s. See the timeline in the next sub-section.
  • Overlap. Windows are 3 s long and start every 1.5 s, so consecutive windows overlap by half.
  • AudioContext sample rate is the device's (44.1 or 48 kHz typically). The worklet resamples linearly (ratio = sampleRate / 48000); at exactly 48 kHz it copies samples through.
  • The mic nodes are chained to destination through a gain of 0 (this.mute), because some browsers do not run a worklet whose output is not connected. No sound is played.
  • File analysis (decodeFile() in audio.js) decodes with an OfflineAudioContext at 48 kHz (the browser resamples), mixes to mono, then sends the whole Float32Array to the worker (transferred). The worker analyses non-overlapping 3 s windows; the last window is zero-padded; a tail shorter than 1 s is ignored.
  • iOS rules. Microphone.start() must run from a user gesture (it is called from the button's click handler). If the context leaves the running state (call, Siri, lock screen) or the track ends, onInterrupted fires and the UI stops listening. app.js requests a Screen Wake Lock while listening (when navigator.wakeLock exists) and re-requests it on visibilitychange. stop() suspends the context instead of closing it so restarting is instant.
  • Module systems. app.js and friends are ES modules (<script type="module">). The worker is a classic worker (new Worker(url) without type: 'module') using importScripts. birdnet-core.js is a plain IIFE attaching BirdNETCore to self/globalThis, so it works as a side-effect import in the page, via importScripts in the worker, and via require in Node.

Live analysis timeline

The ring buffer is read every 1.5 s, but only when the worker is idle. Wn below is the 3 s of audio handed to the model; the first result needs written ≥ WINDOW, i.e. 3 s of audio.

worker → pageerror{message, during?}during is the type of the message being handled (init, location, ...). Errors raised inside the live inference loop have no during

app.js handles all of these in the single worker.onmessage switch.

Backend choice

Implemented in init() / useBackend() in js/engine-worker.js.

  1. Candidates are ['webgl', 'wasm'], or only the forced one when ?backend= is given.
  2. webgl is rejected if tf.setBackend fails (WebGL in a worker needs OffscreenCanvas) or if tf.env().getBool('WEBGL_RENDER_FLOAT32_ENABLED') is false: some mobile GPUs only compute in 16 bits, which corrupts the results.
  3. wasm is the SIMD build, single-threaded: multi-threading needs SharedArrayBuffer, i.e. COOP/COEP headers, which GitHub Pages cannot set.
  4. If nothing works, cpu (pure JavaScript, very slow; the UI says "JavaScript (lent)").
  5. The model is loaded, then one warm-up inference + one timed inference with random noise (benchmark()). If the backend is webgl and took more than 600 ms (and no backend was forced), the worker also benchmarks wasm and keeps the faster one.

Measured on desktop, per 3 s window: WebGL ~70-120 ms, WASM ~185 ms. iPhone 8 is not measured yet; the budget is < 1500 ms.

5The Web Worker

js/engine-worker.js in more detail.

  • Constants: HOP = 1.5 * SAMPLE_RATE, MIN_SCORE = 0.1, MAX_RESULTS = 5.
  • Ring buffer: ring (Float32Array(WINDOW)) written at written % WINDOW; windowBuf is the linearised copy of the latest 3 s handed to the model. written counts samples since listen was switched on; nothing runs until written ≥ WINDOW (the first result comes after 3 s).
  • infer(samples): tf.tensor2d(samples, [1, WINDOW]) → model.predict → output.data(). Tensors are disposed manually; the models are in a TF.js layers format.
  • topScores: indices with score ≥ MIN_SCORE, sorted, top 5. The UI threshold (10-90 %) is applied later in app.js, so the worker floor of 0.1 must stay ≤ the slider minimum.
  • Geo model: geoFilter(points) loads model/geo/model.json with tf.loadGraphModel, predicts on [N, 3], takes output.max(0), then disposes the model. It is loaded on demand and freed right away because memory is tight on an iPhone 8. It is re-run (not cached) every time the page asks, i.e. at startup (computeArea() on ready) and when settings change.
  • Errors are caught in self.onmessage and posted as {type:'error', message, during}.

6The model

Audio model (model/audio)

BirdNET V2.4, TF.js layers model.

Inputfloat32 [batch, 144000]: 3 s, mono, 48 kHz, nominally in [-1, 1]
Output[batch, 6522] sigmoid scores (independent per class, not a softmax)
Output orderSame order as model/species.json: [scientific, French, English] per entry
Weightsfloat16 on disk (TF.js decodes to float32 at load), 7 shards of up to 4 MB

11 classes are not species and must never be shown: Dog, Engine, Environmental, Fireworks, Gun, Human non-vocal, Human vocal, Human whistle, Noise, Power tools, Siren. They live in NON_SPECIES (a Set of scientific-name field values) in js/birdnet-core.js and are filtered in onDetections() and when counting probable species in updateGeoStatus().

Why MelSpecLayerSimple is reimplemented

The model begins with two custom layers, MelSpecLayerSimple, which turn audio into mel spectrograms. The official layer uses tf.signal.stft, which is a naive O(n²) DFT on GPU and takes about 67 s on the Node CPU backend. js/birdnet-core.js replaces it with a CPU implementation (registerMelLayer(tf) registers the class under the same name before the model is loaded). On the official sample: ~1.4 s instead of ~65 s in Node, with a max absolute difference of 8.6e-4 on the scores.

The layer's call() does, per batch item:

  1. Normalise (normalize()): min → -1, max → +1, per window (scale = 2 / (max - min + 1e-6)).
  2. Frame + window: periodic Hann window (like tf.signal.hannWindow), frame step from config.
  3. FFT: radix-2 FFT class; two real frames are packed into one complex FFT (z = a + i·b) and separated afterwards, halving the work.
  4. Keep only the REAL part of the spectrum (Re(A[k]), Re(B[k])), not the magnitude. This is deliberate: it mimics the original Keras layer's complex → float cast.
    Pitfall

    Do not "fix" it to magnitude: predictions would change and npm run check would fail.

  5. Mel filterbank: a sparse filterbank (non-zero range per mel band) applied to the spectrum. The filterbank values come from the layer config inside model.json, not from the code.
  6. Square, then raise to the power 1 / (1 + exp(magnitude_scaling)) (magnitude_scaling is a layer weight, initial value 1.23, overwritten by the loaded weights).
  7. Reverse the mel bins and transpose to [96 mel, 511 frames, 1] (written directly as out[(mels-1-m) * F + f]).

The model has two such layers, configured in model.json:

LayerFrame lengthHopFrequency range
120482780 - 3 kHz
21024280500 Hz - 15 kHz

input.dataSync() in call() is cheap because the input tensor was created from a CPU array in infer() (no GPU read-back). The layer's output is a CPU-built tensor handed to the backend (GPU for WebGL), so the heavy convolutions still run on the chosen backend.

Constants exported by BirdNETCore: SAMPLE_RATE (48000), WINDOW (144000), NON_SPECIES, FFT, MelSpec, normalize, registerMelLayer, birdnetWeek.

Geo model (model/geo)

TF.js graph model (BirdNET's "meta" model).

Input[N, 3] = [latitude, longitude, week]
WeekBirdNET week 1-48, four per month: birdnetWeek(date) = month*4 + min(4, floor((day-1)/7)+1)
Output[N, 6522]: probability that each species occurs at that place and week
CombinationThe worker takes the max over the N points
ThresholdGEO_THRESHOLD = 0.03 in app.js (BirdNET's default)
  • Default area: continental Europe, europePoints(week) in app.js: a grid every 2.5° of latitude 37-60 °N and longitude 10 °W-30 °E. No permission prompt. About 490 species pass in mid-October.
  • "Precise" option: navigator.geolocation.getCurrentPosition → a single point. On refusal or error it silently reverts to Europe and unticks the box. The position is never stored or sent.
  • Filter state in app.js: geoScores (null until computed) and geoArea. While geoScores is null the filter lets everything through.

7Building model/, vendor/ and icons

You only need this when changing the model, TF.js, or the icon. The diagram shows how the generated folders reach the live site (the deployment half is detailed in section 13).

model/: python tools/build_model.py

Requires Python ≥ 3.8 and numpy. The script:

  1. Downloads BirdNET_v2.4_tfjs.zip and BirdNET_v2.4_tflite_int8.zip from Zenodo record 15050749 into .cache/ and checks their MD5 (the int8 zip is used only for labels/fr.txt).
  2. Extracts the official model to .cache/orig/ (needed by npm run check; also contains sample.wav).
  3. Converts weights float32 → float16 by writing the TF.js manifest entry "quantization": {"dtype": "float16", "original_dtype": "float32"}; TF.js decodes on load. A weight whose fp16 error exceeds 1 % (or overflows) would stay float32; currently none do.
  4. Keeps int32 graph constants as-is (non-float32 entries in the geo graph).
  5. Re-shards the output into 4 MB group1-shardNofM.bin files and rewrites model.json.
  6. Writes model/species.json from labels.json (English) + labels/fr.txt, asserting that the scientific names agree line by line and that there are 6522.
  7. Deletes and rewrites only model/audio and model/geo: model/LICENSE.md is left untouched.

The output is deterministic, so re-running without changes produces no git diff. Afterwards: run npm run check, bump VERSION in sw.js, and update model/LICENSE.md if the list of modifications changed.

npm run check: tools/check_model.mjs

Needs npm install and .cache/orig/ from build_model.py. It loads, in Node (TF.js CPU backend):

  • the official fp32 model with a reference tf.signal.stft layer (copy of the official example code), and
  • our fp16 model with the CPU layer from birdnet-core.js,

runs both on .cache/orig/sample.wav (16-bit PCM with a 44-byte header, first 3 s), prints the top 5 of each and the max absolute difference over the 6522 scores. It exits 1 if the difference is greater than 0.02. Run it after any change to birdnet-core.js, build_model.py or model/.

vendor/: npm install && npm run vendor

tools/vendor.mjs copies from node_modules/@tensorflow/: tf.min.js, tf-backend-wasm.min.js, tfjs-backend-wasm.wasm, tfjs-backend-wasm-simd.wasm into vendor/, strips the trailing sourceMappingURL comment from the .js files (the maps are not shipped), and downloads the Apache-2.0 LICENSE from the tfjs repository at tag tfjs-v4.22.0 into vendor/LICENSE-tfjs.txt (the npm package does not include it). The worker loads them with importScripts('../vendor/tf.min.js', '../vendor/tf-backend-wasm.min.js', ...) and tf.wasm.setWasmPaths('../vendor/'). There is no bundler.

Icons: python tools/make_icons.py

icons/icon.svg (a bird drawn with spectrogram bars) is the single source. The script renders it with headless Edge/Chrome and resizes with Pillow (pip install pillow):

OutputSizeNotes
apple-touch-icon.png180Square: iOS rounds the corners itself

The SVG's first <rect> must be the background; the script relies on that.

8User interface

index.html has three views toggled by the bottom tab bar (.tabs button with data-view; handler at the end of app.js):

TabView idContent
Écouterview-listenSpectrogram canvas + loading overlay, listen button, "analyse a recording" file input, detection cards (#detections)
Ma listeview-listLife list cards, export/import buttons
Infosview-infoSettings (threshold slider, geo checkboxes), engine info, install help, credits and licences

Species cards are cloned from <template id="card-tpl"> by makeCard(); the same template serves detections and the life list.

Clip replay. Each detected species keeps the clip of its best-scoring window (d.clip in onDetections(), memory only, cleared with detected; ~576 KB per species). The .play button at the bottom of the card photo calls playClip(): the clip is peak-normalised (gain capped at ×20, distant birds are quiet) and played in a separate AudioContext; a second tap or the end of the clip calls stopClip(). While a clip plays during live listening, the app sends {type:'listen', on:false} and resumes afterwards, otherwise the microphone would re-detect the playback. Life-list cards have no clip (the button stays hidden). On iPhone, playback while the mic is open may come out of the earpiece (quieter): an iOS audio-session limit.

Detection state (app.js): detected (Map: species index → {index, best, last, first, time}) and cards (index → <li>). rerender() is the single place that reconciles state with the DOM: it filters with visible() (threshold and geo), sorts (most recently heard first in live mode, chronological in file mode), removes cards no longer visible, and moves nodes only when needed to avoid scroll jumps. A card gets class live for 4 s (LIVE_MS) after its last detection; a 1 s setInterval refreshes "il y a ..." labels when the tab is visible.

Settings persist in localStorage (see Storage): threshold (default 0.5, slider 10-90 step 5), geo (default true), precise (default false).

9Offline support: the service worker

sw.js is registered from app.js (navigator.serviceWorker.register('sw.js')). It requires HTTPS or localhost; it is verified working on GitHub Pages. (The Claude in-app browser could not register it on http://127.0.0.1; real Chrome/Safari on localhost is fine.)

CacheStrategyContents
piaf-app-<VERSION>network-first, fallback to cache (ignoreSearch)SHELL list: html, js, css, manifest, icon, model/species.json; anything else same-origin that is not heavy
piaf-heavy-<VERSION>cache-firstSame-origin paths containing /model/ or /vendor/ (except species.json)
piaf-externalcache-firstiNaturalist images and Google Fonts (cross-origin requests with a non-empty request.destination; API JSON responses go straight to the network)

On install, SHELL is pre-cached and skipWaiting() is called; on activate, caches not in [APP, HEAVY, EXTERNAL] are deleted and clients are claimed.

Rules for contributors:

  1. Rule

    Bump VERSION whenever model/ or vendor/ change. Heavy files are cache-first, so without a new cache name users would be served stale model/TF.js files forever.

  2. Add every new app file to SHELL (new JS module, new page, new asset) so it works offline from the first visit.
  3. App files are network-first, so ordinary code edits reach users on the next online load without a bump (the first load after a deploy may still run the previous service worker's cached pages if the network is slow; a reload fixes it).
  4. Changing sw.js itself makes browsers re-install it.

10Storage and privacy

All data is in localStorage, per device and per origin:

KeyContentWritten by
piaf:settings:v1{threshold, geo, precise}app.js
piaf:lifelist:v1{ "<scientific name>": {sci, fr, en, first, last, best} }; dates are ISO strings, best is 0-1 rounded to 0.01lifelist.js
piaf:taxa:v1iNaturalist cache { "<sci>": {id, url, photo, attribution, license, licenseUrl, t} }, 30-day TTLspecies-info.js

All reads/writes are wrapped in try/catch (private mode, quota).

Rule

If you change a schema in an incompatible way, bump the :vN suffix and write a migration from the old key.

Life list export is a JSON file {app: 'piaf', version: 1, exported, species: [...]} named piaf-liste-YYYY-MM-DD.json. Import merges: new species are added; for existing ones the earliest first, latest last and max best win. Invalid files raise "Fichier non reconnu". add() also calls navigator.storage.persist() to ask the browser not to evict the data.

iOS caveat: Safari may wipe storage of a site not visited for 7 days unless it is added to the Home Screen. The UI tells users to install it and to export regularly.

Privacy summary: audio is processed locally and never sent; location only if "precise" is ticked, and it stays on the device; iNaturalist receives only a scientific name; no analytics, no cookies.

11iNaturalist photos

js/species-info.js, getSpeciesInfo(sci) returns {id, url, photo, attribution, license, licenseUrl, t} (or {photo: null} / null on failure).

  • Request: GET https://api.inaturalist.org/v1/taxa?q=<sci>&rank=species&per_page=5&locale=fr. Results are matched on the exact name or on matched_term (iNaturalist synonyms).
  • Fallback: if nothing matches, search again without rank=species for species iNaturalist files as a subspecies, and accept a name with the same genus and last epithet (for example Acanthis cabaret → Acanthis flammea cabaret).
  • Only photos with a license_code (Creative Commons) are shown, with the attribution text and a link to the licence deed (licenseUrl()), rendered in the card's .credit line. This is a legal requirement: keep it. Species without a CC photo show an empty frame (the card still links to the taxon page).
  • Rate limit: requests are chained through a promise queue with 1 s spacing (SPACING); iNaturalist asks for roughly 60 requests/min at most. Duplicate in-flight lookups share one promise.
  • Cache: 30 days in piaf:taxa:v1; if the network fails, an expired cache entry is still used.
  • Only the scientific name leaves the device.

12Testing

There is no unit-test framework. Verification is: the model check (automated), a syntax check, and manual scenarios.

Automated

npm install                      # once
python tools/build_model.py      # once (creates .cache/orig/ with sample.wav)
npm run check                    # model + mel layer vs official; must print OK
node --check js/app.js           # syntax check, repeat for each file you touched
node --check js/engine-worker.js
node --check sw.js

node --check works on the ES-module files because it only parses them. Run npm run check whenever js/birdnet-core.js, tools/build_model.py or model/ change.

Manual: desktop

  1. npm run serve, open http://localhost:8080, open DevTools (F12).
  2. Wait for the loading overlay to disappear; the Infos tab should show "Moteur : ...".
  3. Check the console for errors, and Application → Service Workers for sw.js (activated).
  4. Go offline (DevTools Network → Offline), reload: the app must still load and work.

Testing without a microphone

Both recipes use the official sample (.cache/orig/sample.wav, created by build_model.py; served by the dev server because it lives under the repo root). Paste in the DevTools console of the Piaf page.

Recipe 1: analyse a file

Exercises the worker and the file path.

const buf = await (await fetch('.cache/orig/sample.wav')).arrayBuffer();
const dt = new DataTransfer();
dt.items.add(new File([buf], 'sample.wav', { type: 'audio/wav' }));
const input = document.querySelector('#file');
input.files = dt.files;
input.dispatchEvent(new Event('change'));

Expected: Sizerin cabaret around 95 % and Sizerin flammé around 80 %. If they are missing, untick the geo filter and lower the threshold to see whether the filter or the model is responsible.

Recipe 2: fake microphone

Exercises getUserMedia → worklet → worker → live loop.

const ac = new AudioContext();
const buffer = await ac.decodeAudioData(await (await fetch('.cache/orig/sample.wav')).arrayBuffer());
const src = ac.createBufferSource();
src.buffer = buffer; src.loop = true;
const dest = ac.createMediaStreamDestination();
src.connect(dest); src.start();
await ac.resume();
navigator.mediaDevices.getUserMedia = async () => dest.stream;
// Now click « Écouter ».

Expected: the same two species highlighted within about 5 s (3 s to fill the buffer, then one analysis every 1.5 s). If ac stays suspended, click once in the page first (autoplay policy).

To also exercise the resampler, run this before clicking « Écouter » (and reload the page first: Microphone creates its context once):

const Native = window.AudioContext;
window.AudioContext = function (opts) { return new Native({ ...opts, sampleRate: 44100 }); };

The app's context then runs at 44.1 kHz and the worklet resamples to 48 kHz; results must be the same two species. Create the fake-mic context (ac) before installing this wrapper, or via new Native().

13Deployment

Hosting is GitHub Pages, "Deploy from a branch", branch main, folder / (root) (repo Settings → Pages). Every push to main redeploys in about 1-2 minutes. Site: https://yannickriou.github.io/birdnet-web/. The pipeline is drawn in the build and deploy diagram above.

git push origin main
gh api repos/YannickRiou/birdnet-web/pages/builds/latest   # status: "built" when done
Rule

All URLs in the code are relative (sw.js, manifest.webmanifest with start_url: "./", new URL(..., import.meta.url)), so the app works from the /birdnet-web/ sub-path. Keep it that way: never introduce root-absolute paths such as /js/app.js.

Pitfall

Line endings. The repo has .gitattributes (* text=auto eol=lf, plus *.bin, *.wasm, *.png marked binary). On Windows, core.autocrlf=true would otherwise rewrite files and could corrupt binaries or create whole-file diffs. Do not remove it.

Repo identity. Commits are in English; this repo uses a local identity (user.name plus a GitHub noreply email). Set yours with git config inside the repo.

After deploying, open the live site in a private window and confirm that the new service worker activates (Application → Service Workers) and that the Infos tab works.

15How do I... (recipes)

Change the default confidence threshold

  1. In js/app.js: const settings = { threshold: 0.5, ... }.
  2. If needed, change the slider bounds in index.html (#threshold, min="10" max="90" step="5"). The worker floor MIN_SCORE = 0.1 in engine-worker.js must stay ≤ the slider minimum.
  3. Existing users keep their saved value in piaf:settings:v1; the default only affects new users.
  4. Re-test: slider position on first load, cards appear/disappear.

Change the analysis rate (HOP)

  1. In js/engine-worker.js: const HOP = 1.5 * SAMPLE_RATE.
  2. Smaller = more analyses (more CPU/battery, more overlap); larger = fewer. The window must stay WINDOW (3 s): it is the model's input size.
  3. Re-test on a slow device: if inference takes longer than HOP, windows are skipped (by design; see the timeline). Update the "1,5 s" mention in comments and the README if you change it.

Change the default region / grid

  1. In app.js, edit europePoints(week): latitude loop (37 → 60), longitude loop (-10 → 30), step 2.5. More points = slower geo prediction (still one forward pass, N rows).
  2. Update the French texts that say "Europe continentale": updateGeoStatus() in app.js, the checkbox label in index.html, and the README.
  3. If you rename the area id ('europe'), update the geoArea comparisons ('position' is the other id).
  4. Re-test: the species count in the Infos tab, and a few species that should (not) pass.

Add another label language

BirdNET ships labels for many languages in the int8 zip as labels/<lang>.txt: af ar cs da de en_uk en_us es fi fr hu it ja ko nl no pl pt ro ru sk sl sv th tr uk zh. Each line is <scientific>_<common name>, in the same order as the model outputs.

  1. In tools/build_model.py, read another file with int8.read("labels/<lang>.txt"), assert the scientific names match as the French/English loop does, and append the name as a fourth column of each species.json entry (appending keeps indexes 1 and 2 stable).
  2. Run the script, then npm run check.
  3. In app.js, entries are destructured as [sci, fr, en] in rerender(), onDetections() and makeCard(sci, fr, en). Add a language setting (new key in settings, a <select> in the Infos view) and pick the right column. The life list stores fr and en: add the new field to lifelist.js (add(), importFile()) without breaking older saves (do not bump v1 unless you migrate).
  4. Optionally change locale=fr in species-info.js so iNaturalist returns localised names.
  5. Bump VERSION in sw.js (the model folder changed) and update model/LICENSE.md.

Translate the UI

French strings are spread over: index.html (all labels, lang="fr", meta description), app.js (status/hint/error messages, toLocaleDateString('fr-FR'), confirm/alert), lifelist.js (alert), species-info.js (deed.fr in licenseUrl, locale=fr), manifest.webmanifest (lang, name, description), and the BACKENDS labels in app.js. There is no i18n layer: either do a straight replacement or extract strings into one module first. Keep the French licence/attribution wording unless you adapt it.

Change colours or fonts

  1. Edit the tokens in :root of css/app.css. Keep text contrast ≥ 4.5:1 (--moss is decorative only).
  2. Also update <meta name="theme-color"> in index.html and theme_color / background_color in the manifest, the hard-coded #000004 spectrogram background in .spectro, and icons/icon.svg (then re-render the icons).
  3. Fonts: change the Google Fonts <link> in index.html and --font-title / --font-body. Keep fallbacks (offline first visit has no fonts).

Replace the icon

  1. Edit icons/icon.svg (first element must be the background <rect>).
  2. python tools/make_icons.py (needs Pillow and Edge or Chrome).
  3. Commit the SVG and the four PNGs. The SVG is also cached in SHELL, so bump VERSION if you want installed apps to refresh quickly (icons are network-first, so it is not mandatory).

Upgrade TF.js

  1. In package.json, change both pinned versions (@tensorflow/tfjs, @tensorflow/tfjs-backend-wasm) to the same release. In tools/vendor.mjs, update the licence URL tag (tfjs-v4.22.0).
  2. npm install && npm run vendor.
  3. npm run check (Node uses the npm package, so it validates the custom-layer API and the model).
  4. Test in a browser with ?backend=webgl, ?backend=wasm and ?backend=cpu: the custom layer (registerMelLayer) and the WASM paths are the fragile parts. Check the .wasm file names in vendor.mjs still exist in the new package.
  5. Bump VERSION in sw.js, update the version in index.html credits/README if mentioned.

Add a new JS module

  1. Create js/<name>.js as an ES module; import it from app.js (or importScripts it in the worker with a path relative to the worker file).
  2. Add 'js/<name>.js' to SHELL in sw.js and bump VERSION.
  3. Use only relative URLs. Run node --check js/<name>.js.
  4. Add the file to the repository map in this handbook and the README architecture table.

Update the BirdNET model

Change the Zenodo record id, file names and MD5 values at the top of build_model.py, run it, npm run check (the output indexes/shape assumptions: 6522 classes, input 144000, mel layers), bump VERSION, update model/LICENSE.md and the credits in index.html. See also the BirdNET+ note in limitations.

Release checklist

  1. npm run check if anything under model/, birdnet-core.js or build_model.py changed.
  2. node --check on every JS file you touched.
  3. Manual test on a phone (real HTTPS origin): load, listen, stop, file analysis, offline reload.
  4. Bump VERSION in sw.js if model/ or vendor/ changed; add new files to SHELL.
  5. Check licences/credits (section 14) if you added a dependency or changed the model.
  6. Commit (English message), git push origin main, then gh api repos/YannickRiou/birdnet-web/pages/builds/latest until built; smoke-test the live URL.

17Known limitations and ideas

  • Resampler is linear. Fine for 44.1 → 48 kHz (typical mics) but it would alias if a microphone ran above 48 kHz. Add a low-pass filter before decimation if that ever matters.
  • No dark mode.
  • Species without a CC photo show an empty frame.
  • WASM is single-threaded (no COOP/COEP on GitHub Pages). Moving to a host that can set those headers (or using a service-worker header shim) would allow multi-threaded WASM.
  • iPhone 8 timing is not measured yet. Do it before promising anything; the target is < 1500 ms.
  • error messages from the live loop have no during, so the UI cannot distinguish them from a generic error (it only writes the message in the hint).
  • BirdNET+ V3.0 preview exists on Zenodo record 20703646 (ONNX, 11K species, CC BY-SA 4.0, FP16 pruned 72 MB, heavier compute). It would need onnxruntime-web and a new front-end (mel layer) check against the official pipeline. A possible future upgrade; note the licence differs (BY-SA vs BY-NC), so model/LICENSE.md and credits would change.
  • Further ideas, not started: dark mode, per-session history, sharing a list, more label languages.
